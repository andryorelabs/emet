emet が実行をまたいで何を記憶し、それをどこに保存するかを説明します。用語は [GLOSSARY.md](../../GLOSSARY.md) に従います。

## 教訓

実行は無人で行われるため、そこで学んだことはセッションとともに消えてしまいます。実行の終わりに、コーディネーターは、役に立ったこと、または妨げになったことについての 1 から 5 個の短い箇条書きを、**教訓**として保存します。実行の結果（landed、chained、hold、stop、blocked）も一緒に保存されます。各箇条書きは短い 1 行です。

教訓はスペックごとに、リポジトリごとのノートに保存されるので、同じリポジトリでの後の実行は、以前の実行が学んだことを読めます。大きくなりすぎたノートは、古いセクションから順に削除されます。

## 保存場所

教訓は [Engram](https://github.com/Gentleman-Programming/engram) にあります。これは別のローカルメモリストアであり、あなたのリポジトリにもトラッカーにもありません。emet がそれを使うのは、`engram` バイナリが PATH 上にあり、ハンドシェイクに応答するときだけです。

Engram がない、壊れている、またはオフになっている場合、`emet memory` はメモリが利用できないと報告し、正常終了します。メモリが実行をブロックすることはありません。

## 使われ方

実行の開始時、最初のインタビューラウンドの前に、コーディネーターはその機能に合致する教訓をメモリから検索します。関連するものは「Prior lessons」の見出しの下でプランに入るため、インタビューとプランは、以前の実行が見つけたことから始まります。何も見つからない、またはメモリが利用できない場合は、実行はその旨を 1 行で記して先に進みます。

## 手動で使う

`emet memory search` と `emet memory save` は通常の CLI コマンドなので、自分で教訓を検索したり追加したりできます。リポジトリでメモリをオフにするには、`memory.enabled` を `off` に設定します。

コマンドについては [`emet memory`](../reference/cli.md#runs-workers-and-slots) を参照してください。キーについては [`memory`](../reference/configuration.md#memory) を参照してください。大きな流れの中での実行の位置づけは、[実行、ウェーブ、スペック](runs-waves-specs.md)にあります。
