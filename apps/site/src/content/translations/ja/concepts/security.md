無人の実行が引き起こしうる被害を、emet がどのように抑えるかを説明します。用語は [GLOSSARY.md](../../GLOSSARY.md) に従います。脆弱性を報告するには、[SECURITY.md](../../.github/SECURITY.md) を参照してください。

## 無人の実行の脅威モデル

1 回きりの承認の後、`/emet:run` は、誰も見ていない状態でファイルを編集し、シェルコマンドを実行し、コミットするワーカーをディスパッチします。そこから生じるリスクは次のとおりです。

- **破壊的なコマンド。** ワーカー、またはそれが読んだテキストが、再帰的な強制削除、破壊的な SQL 文、強制プッシュを実行します。
- **保護されたブランチへの書き込み。** ワーカーが `main` や `develop` にプッシュし、レビューを飛ばします。
- **ワークツリーからの脱出。** ワーカーがメインのチェックアウトや、別のワーカーのワークツリーを編集します。
- **承認の偽造。** エージェントが、人を待たずに承認記録を自分で書き込みます。
- **信頼できない入力。** チケットのテキスト、コメント、Web ページ、ツールの出力が、エージェントを狙った指示を含んでいます。

コントロールは階層化されています。単一の階層がサンドボックスになるわけではなく、ランディングの PR をレビューすることの代わりになるものもありません。

## 権限モード

Claude Code では、ワーカーは `handoff.permissionMode` の権限モードで動作し、デフォルトは `bypassPermissions` なので、無人のウェーブがプロンプトで止まることはありません。このモードで残るコントロールが `emet guard` フックです。

Codex CLI では、`workspace-write` サンドボックスがリンクされたワークツリーでのコミットと、Codex コーディネーターからの `emet dispatch` をブロックするため、ワーカーはデフォルトでサンドボックスなしで動作します（[ADR-0022](../adr/0022-codex-workers-run-unsandboxed-by-default.md)）。承認はフックの判断であり、`approval.json` を手で書き込むことは拒否されます。[Codex ガイド](../how-to/use-codex.md)を参照してください。

トラッカーに書き込むのはコーディネーターだけで（[ADR-0005](../adr/0005-coordinator-is-the-single-tracker-writer.md)）、ワーカーはローカルブランチにのみコミットします（[ADR-0004](../adr/0004-one-wave-one-dependency-layer-one-pr.md)）。

## ガードがカバーするもの

**`emet guard`**（`emet/src/guard-destructive.ts`）は、ホストにインストールされる PreToolUse フックです。破壊的なシェルコマンドと SQL クライアントを拒否し、`env`、`sudo`、`timeout`、`xargs` などのラッパーを見通し、実行ディレクトリを保護します。

**`rm-guard`**（`.claude/hooks/rm-guard.ts`）は、このリポジトリ自身の Bash 向け PreToolUse フックです。コマンドを `;`、`&&`、`||`、パイプ、改行で分割し（`sh -c` の中のテキストも含みます）、すべての対象が `/tmp` または OS の一時ディレクトリの厳密に下に解決されない限り、再帰的な強制 `rm`（`-rf`、`-fr`、`-r -f`、`--recursive --force`）を拒否します。リポジトリの内側は一覧に含まれないため、`.emet/` の下での再帰的な強制削除も拒否されます。`$`、バッククォート、`~` を使う対象は、解決できないため拒否されます。

`.claude/settings.json` の**プッシュの拒否**は、`git push origin main` と `git push origin develop`、および `HEAD:main` と `HEAD:develop` の形式をブロックします。`pre-push` Git フックは、同じ ref と、許可されたパターンに合わない任意のブランチ名を拒否します。タグのプッシュは許可されます。

**ルールセット**は、GitHub 上で同じルールを強制します。`main` と `develop` の削除と non-fast-forward の禁止、必須チェック、保護された `v*` タグです。[development.md](../development.md#rulesets) を参照してください。

## カバーしないもの

- ガードが認識しないコマンド。たとえば、ディスクに書き込まれて後で実行されるスクリプトです。
- ネットワークアクセス。ワーカーは、認証情報が許す任意の API を依然として呼び出せます。
- ワークツリーの外にあるファイルの読み取り。
- `bun install` によってインストールされる悪意のある依存関係。

チケットのテキスト、コメント、取得したページはデータとして扱ってください。マージする前にランディングの PR をレビューし、実行が引き継ぐ環境にシークレットを置かないでください。
