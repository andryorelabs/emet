每个 `emet` 子命令、关卡与记录表、退出码和环境变量。术语遵循 [GLOSSARY.md](../../GLOSSARY.md)。返回 [README](../../README.md)。每个命令都可以用 `--help` 打印其用法。

## 子命令

在 Claude Code 内，有三个斜杠命令封装了 CLI：`/emet:run`（流水线）、`/emet:init`（`emet init`）和 `/emet:doctor`（`emet doctor .`）。在 Codex 上它们是 `$emet:run`、`$emet:init` 和 `$emet:doctor` 技能。在普通终端中使用 `emet` 需要 `emet self install`；否则请在会话中运行 `! emet <subcommand>`。

`emet <command> [...args]`。`emet --version` 打印版本号。

### 设置与审计

- `emet migrate [--dry-run]`：将旧版仓库重命名为 emet 的名称。
- `emet init [--tracker linear|github|local] [--after-spec release|promote|none] [--force]`：自动检测包管理器、主干分支、跟踪器类型和 after-spec 模式（参见 [`handoff.afterSpec`](configuration.md#handoff)），在发现 Prisma 模式（`prisma/schema.prisma` 或 `prisma/schema/` 文件夹）或 Drizzle 迁移文件夹（`drizzle.config.*` 旁的 `drizzle/`）时设置 [`schema.ownedPaths`](configuration.md#schema)，并写入 `emet.config.json` 和 `docs/agents/*.md` 文件。`--tracker local` 会设置本地跟踪器。
- `emet doctor [--all] [<path> ...]`：以只读方式一次审计任意数量的仓库；默认为当前目录。另外，对于配置了 [`verify.browser`](configuration.md#verify) 的仓库，它还会报告一项可选的 `agent-browser` 检查结果：缺少该二进制文件为 `indeterminate`（带安装补救办法的 `optional:` 行），二进制文件存在时，`agent-browser doctor` 失败会显示为警告。两者都绝不算错误，也不会改变退出码。没有 `verify.browser` 的仓库不显示任何内容。
- `emet setup [--yes] [--with <ids>] [--list] [--json] [--dry-run] [--restore <id>]`：通过 readline 提示提供可选安装项：`mattpocock-skills`（默认开启）、`engram`、`mascot`、`orca-pet`、`gh-auth`、`agent-browser`（默认关闭；运行 `bun add -g agent-browser@latest`，然后运行 `agent-browser install`，仅当 `~/.agent-browser/config.json` 不存在时，才写入包含 `contentBoundaries: true` 和 `maxOutput: 50000` 的该文件，再运行 `agent-browser doctor`，失败时打印警告；从不固定版本，也从不传入 `--with-deps`，因此缺少系统库时，它会打印出供你自行运行的命令）、`context7`（默认关闭；运行 `bun add -g ctx7@latest`，然后运行 `ctx7 setup --cli --claude --yes`，仅当 `codex` 在 PATH 中时才运行 `ctx7 setup --cli --codex --yes`；安装 `ctx7` CLI 及其 `find-docs` 技能，而不是 MCP 服务器，从不固定版本，并在某个 `ctx7 setup` 步骤失败时打印供手动运行的命令；除非设置了 `CTX7_TELEMETRY_DISABLED=1`，否则 `ctx7` 会发送匿名使用事件，且环境中的 `CONTEXT7_API_KEY` 优先于 `ctx7 login` 保存的账户）、`firecrawl-local`（默认关闭；需要 `cargo`，在二进制文件缺失时运行 `cargo install firecrawl-local`，然后以 `FIRECRAWL_CLOUD=search` 和 `--public-only` 注册一个用户级 Claude Code MCP 服务器，并替换设置不同的早期注册：scrape、crawl 和 map 在本机运行，只有网页搜索会发送到 Firecrawl Cloud，并会阻止私有地址。它会把 `agent-browser` 下载的最新 Chrome 作为 `FIRECRAWL_CHROME_PATH` 传入；在 AppArmor 限制非特权用户命名空间的 Linux 上，它会打印一份 AppArmor 配置文件以及加载它的 `sudo` 命令，因为 Firecrawl Local 从不在没有沙箱的情况下运行 Chrome。没有可用的 Chrome 时，使用 JavaScript 渲染的页面会返回空内容）以及推荐的 Claude Code 设置（`claude-settings`，仅在被选中时应用，并先对 `settings.json` 做带时间戳的备份）。没有 TTY，或使用 `--yes` 或 `--with` 时，它不会询问任何内容，只安装指定的项目；没有 TTY 且没有 `--with` 时，它什么都不安装，并打印 `--list` 目录。每一步都会报告 `installed`、`already-present`、`skipped` 或 `failed`；一个失败不会阻止其他步骤，只要有失败，退出码就是 1。`/emet:setup` 是插件入口，通过 `AskUserQuestion` 询问相同的选项。
- `emet setup --dry-run`（可与 `--with`、`--yes`、`--json` 组合）：仅用只读探测，为每个选中的项目打印计划步骤（或 `already-present`），不执行任何操作：不运行命令、不写文件、不写台账，退出码为 0。
- Setup 台账：`setup-ledger.json` 位于状态目录（先看 `EMET_STATE_DIR`，再看 `XDG_STATE_HOME`）。每个结果为 `installed` 的项目记录一条撤销信息（`claude-settings` 记录之前的 `model`、实际添加的 deny 规则和备份路径；`firecrawl-local` 记录之前的用户级 MCP 条目以及是否运行过 `cargo install`；插件记录插件 id；`orca-pet` 记录它写入的文件；`agent-browser` 和 `context7` 记录 bun 全局包；`engram` 记录 brew formula 和插件）。`already-present` 的项目不记录任何内容，同一 id 再次 `installed` 时保留第一条记录的原始状态。写入是原子的。格式错误的台账不会被当作空台账读取，而是报错并指出其路径。
- `emet setup --restore <id>`：只接受 `claude-settings` 和 `firecrawl-local`。`claude-settings` 在带时间戳的备份之后恢复之前的 `model`（原本没有则删除该键），并且只移除 emet 添加的 deny 规则。当前 `model` 不是 setup 设置的值时，保留它并打印警告。`firecrawl-local` 运行 `claude mcp remove firecrawl-local -s user`，如果记录过之前的条目，再运行 `claude mcp add-json firecrawl-local '<previous json>' -s user`。恢复成功后会删除对应的台账条目。其他 id 以退出码 2（用法错误）结束；台账中没有条目的 id 会打印 `nothing to restore for <id>` 并以退出码 1 结束。
- `emet self install [latest|X.Y.Z] [--dry-run] [--force] [--from <checkout>]`：独立安装。它把二进制文件放到 `~/.local/share/emet/versions/<v>/emet`，并创建符号链接 `~/.local/bin/emet`；把参考提示词和 `.install-manifest.json` 写入 `~/.claude/emet/`，命令写入 `~/.claude/commands/emet/`，代理写入 `~/.claude/agents/`；把 emet 钩子合并进 `~/.claude/settings.json`（带备份，不触碰其他钩子）；当存在 Codex 时，还会把技能写入 `~/.agents/skills`，并把钩子追加到 `$CODEX_HOME/hooks.json`（默认 `~/.codex`；绝不写入 `config.toml`，因此需用 `/hooks` 批准一次这些钩子）。再次运行不会有任何改动；被编辑过的文件会保留，新版本写在旁边，命名为 `<file>.new`。`--dry-run` 列出每一次写入但不写入任何内容。当 emet 插件已安装时它会拒绝执行；`--force` 则强行继续。`--from <checkout>` 复现 Bun 源码安装：CLI 源码被复制到 `~/.claude/emet`，`~/.local/bin/emet` 变成一个用 `bun` 运行它的包装脚本，因此 `emet selftest` 可用；没有 `bun` 时会失败。贡献者使用 `emet self install --from .`。单行命令 `curl -fsSL https://emet.andryore.dev/install.sh | sh` 会下载发布的二进制文件，验证 `SHA256SUMS`，然后运行此命令。
- `emet self update [latest|X.Y.Z]`：下载发布版本，验证 `SHA256SUMS`（存在 `gh` 时还验证证明），并将其暂存。只有在没有持有任何 worker 槽位时，才会切换符号链接和已安装文件；否则它保持待处理状态，直到下一次会话启动。失败不会改动当前版本，并会记录在日志中。上一个版本会保留以便回滚，更早的版本会被清理。对插件安装它不做任何事。`emet self update --auto [off|on]` 是 `SessionStart` 钩子运行的命令：每天最多一次，在后台分离运行，离线时保持静默；`off` 或 `on` 用于切换开关。`EMET_AUTO_UPDATE=0` 同样会将其禁用。
- `emet uninstall [--dry-run] [--yes] [--purge] [--json]`：移除 `emet self install` 的安装以及 `emet setup` 添加的内容。删除安装清单中当前哈希与记录哈希一致的每个文件，以及它的 `.new` 同名文件。已被编辑的文件会保留并列出。仅当 shim `~/.local/bin/emet` 是该安装的包装脚本，或是指向 `~/.claude/emet` 的符号链接时才删除它，随后删除清单和变空的目录；指向安装之外的 shim 会保留并列出。没有清单时（插件安装）跳过这些文件，并打印 `claude plugin uninstall emet@emet-marketplace`。当 `codex` 在 PATH 中时，会打印如何移除 Codex 插件。对于 `~/.claude/settings.json`，只删除任意事件中命令为 `emet guard` 的钩子（清除变空的分组和事件，保留其他所有钩子，并先生成带时间戳的 `.pre-emet-guard-backup.` 副本），并还原台账中的附加项（`claude-settings` 和 `firecrawl-local` 同上；插件运行 `claude plugin uninstall <id>`；`orca-pet` 的文件和 emet 创建的 `agent-browser` 配置文件会被删除）。对于 brew、bun 和 cargo 的全局包，只打印移除命令而从不执行，也绝不触碰 `gh auth`。每个已还原的条目都会从台账中移除，某个附加项失败不会阻止其他项。`--dry-run` 打印完整计划，不做任何更改，退出码为 0。`--yes` 跳过确认，`--purge` 还会删除状态目录和 `~/.emet`（不带它则两者都保留）。有 TTY 且没有 `--yes` 时会询问一次确认；没有 TTY 且没有 `--yes` 时打印计划，不做任何更改，退出码为 0。任何步骤失败时退出码为 1。
- `emet fleet list [--root <dir>] [--json]`：列出 `--root`（默认 `~/code`）下一层、带有 `emet.config.json` 的 git 仓库，并显示 `tracker.kind`、`handoff.autoChain` 和 `models.worker`。`emet fleet set <key> <value> [--root <dir>] [--dry-run]` 会在每个列出的仓库中修改一个配置键，并先通过配置加载器校验（无效值不会改动任何内容，并以退出码 1 结束）。`emet fleet launch --feature <text> [--root <dir>] [--repos <a,b>] [--dry-run]` 在通过 `emet chain` 的就绪检查后，在每个仓库中打开一个 `/emet:run --draft <text>` 会话。`[--dry-run]` 会打印计划的启动内容，而不会启动会话。参见 [fleet 指南](../guide/fleet.md)。
- `emet fleet status [--json]`：读取全局 journal，按仓库打印每个会话在最近 24 小时内的最新状态（不含 `ended`）。`--json` 打印 `{ repos: [{ repo, sessions: [{ sessionId, state, blocked, since, runId }] }], blocked: <count> }`；否则每个仓库打印一行 `<repo>: <b> blocked, <w> working, <i> idle`，被阻塞的仓库排在最前。为空时同样以 0 退出。参见[查看被阻塞的会话](../guide/fleet.md#查看被阻塞的会话)。
- `emet preflight [--run <id>] [--post-dispatch]`：确认仓库已具备派发条件。
- `emet skill-path <name>`：打印某个 mattpocock-skills 技能的 `SKILL.md` 绝对路径。如果找不到该技能，则以退出码 1 退出。
- `emet selftest`：运行 CLI 自身的单元测试。仅限源码安装；已编译的二进制文件会以退出码 1 退出，并提示你运行 `emet doctor`。

在任意 git 仓库中：

```bash
emet init          # autodetects package manager, trunk branch, tracker kind
emet preflight      # confirms the repo is dispatch-ready
```

对于 `emet init` 无法自行推断的内容（共享测试数据库锁、模式归属等），它会在生成的 `docs/agents/*.md` 文件中留下 `TODO(emet):` 标记；请把这些内容补全。只要还有标记残留，`emet preflight` 就会拒绝派发。

然后，在 Claude Code 中（在 Codex 上，使用 `$emet:run` 并传入相同参数）：

```text
/emet:run <describe the feature>              # interview → wave 1; later waves via --dispatch/autoChain
/emet:run --draft <describe the feature>      # stop after tickets are created
/emet:run --dispatch <spec-id>                # dispatch a --draft'd spec later
```

#### 批量检查

`emet doctor` 可以以只读方式一次审计多个仓库：

```bash
emet doctor ~/code/*
```

它会逐个仓库报告：`emet.config.json` 是否有效、四个 `docs/agents/*.md` 文件是否齐全、是否没有遗留的 `TODO(emet):` 标记、`commands.selfCheck` 中的命令是否真的可以解析，以及该仓库与跟踪器相关的依赖检查结果（`gh`、Linear，参见[依赖](dependencies.md#谁检查什么)）。mattpocock-skills 插件和外部 CLI 的标志（`gh`，以及代理宿主的标志：Claude Code 上是 `claude --bg` 和 `claude agents --json`，Codex 上是 `codex exec --json` 和 `--output-schema`，通过 `--help` 检查）在整次扫描中只检查一次，而不是每个仓库检查一次。

### 运行、工作者与槽位

- `emet claims --reserve <ticket> --run <id> --anchor <pid>`：为某次运行预留一个工单。`--release <ticket>`、`--list` 和 `--prune [--dry-run]` 分别用于释放认领、列出认领，或清理过期的认领。
- `emet slots --acquire --run <id> --anchor <pid> --ticket <ticket>`：从 `~/.local/state/emet/slots` 中的主机级池获取一个工作者槽位。`--release --run <id>`、`--release-index <index>` 和 `--list` 用于释放或列出槽位。
- `emet cleanup [--run <id> | --all] [--dry-run] [--force]`：不带参数时，回收其工作已落地的已关闭或已终止的运行；`--run` 清理该次运行；`--all` 是对整个仓库的分支清扫。合并之后，`emet cleanup --run <runId>` 会释放该波次的分支、工单认领和工作者槽位。在所有模式下，它还会删除其 PR 已在分支顶端提交处合并的每个本地分支，以及持有该分支的干净且未锁定的代理工作树。
- `emet lock-reason --run <id> --ticket <ticket> [--anchor <pid>]`：打印工作者在引导阶段写入的 `git worktree lock` 原因。
- `emet launch <spec-id> --wave <n>`：在 Claude Code 上，以 `claude --bg` 会话启动一个波次，并按 `handoff.launcher` 打开它的 Orca 标签页（Codex 参见 [Codex 宿主](#codex-宿主)）。它会完成整个启动流程（重复会话检查、`claude --bg`、标签页），并打印 `{ name, id, attach, orcaTab: { opened, reason } }`。每当你想手动在另一个会话中运行某个波次时，请使用它，而不是直接使用 `claude --bg`。
- `emet chain --ticket <id> --spec <id> --wave <n> [gate flags]`：用收到的关卡标志运行 `emet gate`，仅当决定为 `chain` 时才启动下一个波次。启动前它会检查就绪情况（主机内存余量、仓库和 `/tmp` 的可用磁盘与 inode、`orca` CLI），之后确认子会话已列出。任何其他决定、阻塞性的就绪问题（`low-memory`、`low-disk`、`low-inodes`、`orca-unavailable`）或同一规格和波次已有会话时，会连同原因以退出码 1 结束，且不启动任何内容。
- `emet status [--spec <id>] [--brief]`：以 JSON 加一行摘要的形式给出每个波次的 Working / Checking / Ready / Needs-decision 状态。`--brief` 则最多输出三行：整体状态、等待人处理的事项（如有）以及下一步操作。`emet status --help` 说明了该 JSON。其 JSON 新增 `sessions: [{ sessionId, state, blocked, since, runId }]`：此仓库每个会话在最近 24 小时内最新的 `session.attention` 事件，不含 `ended`。`blocked` 即 `state === "needs-decision"`，`since` 是该事件的 `ts`。任何被阻塞的会话都会让整体 `state` 变为 `needs-decision`（即使没有波次），摘要行会说明有多少会话被阻塞，`--brief` 会在“等待人工”那一行列出它们。
- `emet run current [--json]`：输出仓库当前的活动运行（运行 id、规格、波次、阶段和最近更新），读取自 `.emet/phase.json`。没有活动运行时输出 `no active run` 并以 0 退出。
- `emet memory search --json <query> [--limit <n>]`：在 [Engram](https://github.com/Gentleman-Programming/engram) 中搜索以往运行的经验教训。它以 `match_mode: "any"` 搜索（`--limit` 默认 5，最大 20），只保留 topic key 以 `emet/<repo>/lessons/` 开头的笔记，并输出 `{available: true, results: [{id, topicKey, title, content}]}`，其中 `content` 截断为 2000 个字符。`<repo>` 是 `git remote get-url <repo.remote>` 去掉 `.git` 后的最后一个路径段，否则取主 worktree 的目录名。
- `emet memory save --json --key <spec-<id>|quick-<runId>> --run <runId> --outcome <landed|chained|hold|stop|blocked>`：从 stdin 读取 1 到 5 条经验要点（以 `- ` 开头、每条最多 300 个字符的行），并将其作为 `## <runId> — <outcome> (<date>)` 小节追加到 topic key 为 `emet/<repo>/lessons/<key>` 的笔记中，或新建该笔记。超过 20000 个字符的笔记会丢弃最旧的小节。输出 `{available: true, saved: true, topicKey}`。
  - 两个子命令都通过在仓库根目录启动 `engram mcp --tools=agent` 与 Engram 通信；不需要 Engram 插件。它们从不向 Engram 传递 `project`。
  - 退出码：用法错误时为 `2`（没有子命令、缺少查询、没有要点、超过 5 条要点、某条要点超过 300 个字符、未知的 outcome、错误的 key）。Engram 的任何问题（不在 PATH 中、握手失败、工具错误、超时、JSON 格式错误）都以 `0` 退出。握手成功之前输出为 `{available: false, reason}`；之后，`search` 输出 `{available: true, results: [], reason}`，`save` 输出 `{available: true, saved: false, reason}`。`memory.enabled: "off"` 输出 `{available: false, reason: "memory.enabled is off"}`，且不启动任何进程。参见 [`memory`](configuration.md#memory)。
- `emet insights [--since <iso|7d|30d>] [--repo <path>] [--all] [--json] [--mark-baseline]`：读取[事件日志](../guide/journal.md)，按来源（人工或自动）报告运行、按决定和原因报告 gate 决定、每次运行的人工干预、启动结果和已关闭的工单。无法读取的行会被跳过并计数。`--mark-baseline` 追加一个基线；之后的报告只涵盖基线之后的事件，除非指定 `--all`。日志为空或不存在时输出零值报告并以 0 退出。
- `emet usage [--session <id> | --file <path>] [--stalled [--minutes N]] [--project-dir <path>]`：报告会话用量；`--stalled` 列出停滞的工作者。
- `emet handoff --check <path> [--expect-skills a,b] | --render <path>`：校验或渲染工作者的 `.emet/handoff-<ticket>.md` 笔记。笔记可以包含 `skills:` 部分，写作 `skills: none` 或 `skills: loaded: a, b; missing: c`；只有当 `state` 为 `done` 时才必须填写，其他任何值都会使校验失败。`--expect-skills a,b`（仅用于 check）会对每个既不在 `loaded` 也不在 `missing` 列表中的指定技能判定校验失败。当 `missing` 列表不为空时，通过的校验会输出 `missing skills: …`。
- `emet metrics [--run <id>]`：根据会话记录，按工单、按波次和按运行报告 token、折合 API 的成本和耗时。它还会比较每个工单预估的上下文预算与各工作者实际使用的量。其摘要会放在该次运行最终报告的末尾。

### 规划、评审与落地

- `emet promote --spec <id> [--dry-run] [--no-promote] [--hold]`：after-spec 步骤，依据 [`handoff.afterSpec`](configuration.md#handoff)。在 `promote` 模式下，它会打开一个标题为 `chore: 🔖 promote develop` 的从 `develop` 到 `main` 的拉取请求，用 `emet ci --pr <n> --wait` 等待，仅当状态为 `pass` 时才以合并提交的方式合并，然后仅在 `develop` 落后于 `main` 时，打开一个从 `main` 到 `develop` 的同步拉取请求，以同样的方式等待其检查，并仅当状态为 `pass` 时才以合并提交的方式合并；状态为 `fail`、`timeout` 或 `env-fault`，或合并被拒绝的同步拉取请求会保持打开，且从不改变 promote 的结果。它会向日志追加一条带有拉取请求编号、`merged`、`syncPrNumber`、`syncMerged`、`syncReason`、`rule` 和 `reason` 的 `promote` 事件。`afterSpec` 可以是规则列表；此时模式由提升 `develop` 会带来的路径来选择（参见 [`handoff.afterSpec`](configuration.md#handoff)），而 `git fetch` 或 `git diff` 失败会让该命令在打开任何拉取请求之前以 1 退出。打印出的结果包含 `rule`（匹配规则的索引，字符串形式或无匹配时为 `null`）、`reason`、`syncPrNumber`（未打开同步拉取请求时为 `null`）、`syncMerged` 和 `syncReason`（说明同步拉取请求为何保持打开的一句话，否则为 `null`）以及 `deployCheck: { run, reason }`，后者说明协调器是否应运行 `emet deploy-check`。在 `release` 模式下，它不合并任何内容，发布拉取请求留给人来处理。当 `afterSpec` 为 `none`、使用 `--no-promote`，或规范的最后一个波次被保持打开或被标记时，它以退出码 0 结束并附带 `skipped` 说明；它仍会在干净的最后一个波次之后运行，使结果包含 `deployCheck` 的决定（在主干 `main` 上，无论哪种模式都会运行部署检查）。CI 不是 `pass` 时不合并任何内容，并以退出码 1 结束。`--dry-run` 不会打开拉取请求。 `emet promote --spec <id> --hold` 会写入标记 `<run dir>/runs/<id>/no-promote` 并输出 `{"held":true}`；标记存在期间，`emet promote --spec <id>` 以 0 退出并给出 `skipped` 提示，不会打开任何 pull request，因此 `--no-promote` 会在一个规范的多个会话之间保持。
- `emet deploy-check [--json]`：运行 `deploy.check.command`，直到它以 0 退出，最多尝试 `retries` 次或 `timeoutSeconds` 秒，每次之间等待 `intervalSeconds` 秒，并打印 `state: ok | failed | timeout` 以及 `attempts`。退出码 `0` 为 ok，`1` 为 failed，`3` 为 timeout。未配置 `deploy.check` 时，它以退出码 0 结束并输出 `skipped: "no deploy check configured"`。仅当 `emet promote` 的结果中 `deployCheck.run` 为 true 时，协调器才会运行它。参见 [`deploy`](configuration.md#deploy)。
- `emet validate --spec <id> | --file <path>`：计划校验；参见[关卡与记录](#关卡与记录)。
- `emet surfaces --check <file.json | ->`：如果同一波次的工单之间，允许编辑范围的 glob 存在重叠，则予以拒绝。
- `emet approve --run <id>`、`emet materialize-log`、`emet results`、`emet verify`、`emet review-package`、`emet review`、`emet gate`：参见[关卡与记录](#关卡与记录)。
- `emet assess --base <ref> --head <ref>`：将 diff 分类为 `passive`、`medium` 或 `high`，并输出包含层级、原因以及推荐的评审者模型和推理强度的 JSON，外加 `browserVerify: { run, reason }`：仅当该层级有评审者、已配置 [`verify.browser`](configuration.md#verify)、`agent-browser` 二进制文件在 PATH 中，并且在设置了 `paths` 时有变更路径匹配，`run` 才为 `true`；否则 `reason` 会指出第一个未满足的条件。还会输出 `dualReview: { run, reason }`：仅当层级为 `high`、`agentHost` 为 `claude`、[`review.dual`](configuration.md#review) 不为 `off` 且 `codex` 二进制文件在 PATH 中，`run` 才为 `true`；否则 `reason` 会指出第一个未满足的条件。使用 `--quick` 时，JSON 还会包含 `"quickRejected": true|false`，且当层级为 `high` 时命令以退出码 1 退出（对 **Quick run** 而言是一次 **Stop**：不自动合并，PR 保持打开），否则退出码为 0；不带 `--quick` 时输出和退出码不变。参见[模型与推理强度](../../README.md#models--effort)和 [`review`](configuration.md#review)。
- `emet land --spec <s> --branch <integration> --tickets <id,...>`：将集成分支合并到本地主干（`landing.mode` 为 `merge`）。用 `commands.selfCheck` 代替 CI，并且不推送任何内容。
- `emet spec-branch ensure|integrate|status|sync|land|abandon --spec <id>`：`landing.unit: spec` 的规格分支 `spec/<id>`（参见 [`landing`](configuration.md#landing)）。均输出 JSON。`ensure` 从主干创建该分支（幂等），写入 `.emet/specs/<id>/branch.json`，并在另一个规格的分支已被检出时拒绝执行。`integrate --wave <n> --branch <integration> --tickets a,b` 以 `--no-ff` 把波次分支合并到 `spec/<id>`，带上 trailer `Emet-Wave` 和 `Emet-Tickets`，记录该波次，追加 `spec.integrate`，并且在 `landing.pushSpecBranch` 为 true 时推送该分支而不打开 PR。`status` 输出 `branch`、`tip`、已集成的波次和工单以及 `behindTrunk`，并在缺少某个波次时根据 trailer 重建 `branch.json`。`sync` 把主干合并到分支，从不变基；遇到冲突时中止、列出路径并以非零状态退出。`land [--partial]` 先同步，然后在 `pr` 模式下推送分支、打开一个 PR（每个工单一行 `Closes`），等待其检查通过，并以 `landing.specMergeMethod` 合并（默认是合并提交，忽略 `pr.mergeMethod`），在 `merge` 模式下以 `--no-ff` 合并到本地主干且从不推送；它会追加 `spec.land`。`abandon --force` 会打上 `abandoned/spec-<id>` 标签、删除分支、追加 `spec.abandon`，并把本地跟踪器中已集成的工单重置为 `ready-for-agent`；没有 `--force` 时它拒绝执行。`emet tracker frontier` 把 `branch.json` 中列出的工单算作已关闭的阻塞项，`emet status` 新增 `specBranch`（`branch`、`tip`、`integratedWaves`）。
- `emet spec-merge --spec <id>`：将规格中 `ADDED`/`MODIFIED`/`REMOVED` 的需求增量合并到 `docs/specs/<area>.md`（`specs.dir`）。当 `specs.enabled` 开启时，协调者会写入这些增量，并在最后一个波次的集成分支上、评审之前，对每个规格运行一次该命令，然后提交结果。`--deltas-dir` 会打印存放增量的目录。它会在写入任何内容之前检查所有区域。如果出现冲突，或者某个需求会丢失一个场景，则以退出码 1 退出，并且不改动任何文件。当 `specs.enabled` 关闭时，它不合并任何内容并以 0 退出。
- `emet map [--refresh]`：把现有代码库的概览（技术栈、结构、约定、测试、热点）写入 `docs/agents/codebase.md`（`map.path`），并标注生成它所用的提交 SHA。同一个提交总是生成同一个文件。一旦 HEAD 越过该标注，`emet map --stale` 就以退出码 1 退出，此时 `emet preflight` 会发出警告。`emet map --for <globs>` 只打印与工单编辑范围相匹配的部分；该输出是地图中唯一会包含在工作者简报里的部分。
- `emet tracker create-spec|create-ticket|read|frontier|set-state|comment|close`：基于 `.scratch/` 的本地跟踪器，标准输出为 JSON。参见[本地跟踪器](#本地跟踪器)。
- `emet guard`：Claude Code 的 `PreToolUse` 钩子；从标准输入读取钩子 JSON（Codex 的形式见 [Codex 宿主](#codex-宿主)）。`emet self install` 会把它接入 `~/.claude/settings.json`。它会阻止少数已知会导致无人值守运行失败的操作（参见 `emet/src/guard.ts`）。

### 本地跟踪器

设置 `tracker.kind: "local"` 后，规格和工单是主工作树 `.scratch/` 下的 Markdown 文件（不纳入版本控制）：`.scratch/<slug>/spec.md` 和 `.scratch/<slug>/issues/<NN>-<slug>.md`，每个文件都带有 `Status:` 和 `Blocked by:` 行，评论位于 `## Comments` 之下。协调者通过 `emet tracker`（`create-spec`、`create-ticket`、`read`、`frontier`、`set-state`、`comment`、`close`）读写它们。`emet init --tracker local` 会完成这一设置。参见 [ADR-0011](../adr/0011-local-tracker-scratch-convention.md)。

`landing.mode` 为 `"pr"`（默认）或 `"merge"`，与跟踪器无关。在 `merge` 模式下，波次通过 `emet land` 以一次本地合并落地到主干，用 `commands.selfCheck` 代替 CI，并且不推送。设置 `landing.unit: "spec"`（默认）时，整个规格通过 `emet spec-branch land` 一次落地。只有当跟踪器是 `github` 或落地方式是 `pr` 时才需要 `gh`。参见 [ADR-0010](../adr/0010-local-merge-landing.md) 和 [`landing`](configuration.md#landing)。

### 以 PR 落地与串联波次

设置 `landing.unit: "wave"` 时，一个波次对应一个 PR；设置 `"spec"` 时，一个 PR 涵盖所有已集成的波次。其正文为每个工单带有一行 `Closes #N`（跟踪器的关闭关键字），协调者在打开 PR 时会把工单移到评审中。随后，PR 按 `pr.autoMerge` 合并；如果该波次被标记、`autoMerge` 为 `false`，或 CI 修复次数已用尽，则 PR 保持打开（此时 PR 会带上需要人工决定的标签）。后续波次在各自的会话中运行，绝不会在运行波次 1 的那个会话中运行。接下来会发生什么，由 `pr` 和 `handoff` 部分控制；参见 [`pr`](configuration.md#pr) 和 [`handoff`](configuration.md#handoff)。

`emet ci --pr <n> --wait [--rerun-flakes] [--timeout-minutes <m>]` 轮询 PR 的检查，直到检查结束或超时（默认 30）。使用 `--rerun-flakes` 时，每个失败的检查会通过 `gh run rerun --failed` 重跑一次；重跑后通过的检查属于 Flake。它打印 `state: pass | fail | env-fault | timeout`、失败的检查和 `flakeReruns`，且从不合并。没有检查的 PR 为 `pass` 并带有 `noChecks: true`。退出码 `0` 为 pass，`1` 为 fail 或 env-fault，`3` 为 timeout。`env-fault` 指以 `STARTUP_FAILURE` 结束或排队过久的检查：即 CI 从未运行，而不是代码失败。

当 `tracker.kind: "github"` 时，`emet tracker close <ticket>... [--pr <n>]` 用 `gh issue close --reason completed` 关闭每个工单（`CLA-<n>`、`#<n>` 或纯数字），验证其状态并报告 `closed` 或 `already-closed`。`--pr` 会添加评论 "Landed in #<n>"。处理完工单后，它会读取每个已关闭工单的父规格 issue（`gh issue view <n> --json parent`），当 `subIssuesSummary` 显示所有子 issue 均已完成时，会以评论 "All <total> tickets landed." 将该规格按 completed 关闭，并在 `specs` 中报告为 `closed`、`open`、`already-closed` 或 `failed`；读取或关闭规格失败时同样以 `1` 退出。如果有工单失败，它会在处理完其余工单后以 `1` 退出。Linear 工单由协调者通过 Linear MCP 确认为 Done。

### Codex 宿主

这些命令服务于 Codex Agent 宿主（`agentHost` 为 `"codex"`）；参见 [Codex 指南](../guide/codex.md)。

- `emet dispatch --role worker --run <id> --ticket <id> --prompt-file <file> [--model <m>] [--effort <e>] [--root <dir>]`: 在检查认领和槽位之后，创建 `.emet/worktrees/agent-<ticket>`，构建每次运行的 `CODEX_HOME` 覆盖层，并把 worker 作为分离的 `codex exec` 启动。`emet dispatch --wait --run <id> --ticket <id> [--timeout <s>]` 会阻塞到它退出，并输出记录的结果状态。
- `emet review-run --run <id> --ticket <id> --package <file> --tier <medium|high|passive> [--browser-verify true|false]`: 对 `emet review-package` 生成的包，以只读的 `codex exec` 运行 reviewer，并输出供 `emet review --findings` 使用的问题 JSON。`passive` 档不会启动进程。 `--browser-verify` 默认为 `false`；设为 `true` 时，提示词以 Browser 维度结尾，其中 `--session review-<run>` 由 `--run` 填入，这样 Codex 评审者就能像 Claude 评审者一样验证 UI（当 `emet assess` 输出 `browserVerify.run: true` 时传入；参见 [`verify`](configuration.md#verify)）。不带该标志时提示词不变，`true` 或 `false` 之外的值会以退出码 2 退出并输出用法行。`--coverage-out <file>` 还会把 Codex 评审者的 Coverage verdicts 以 JSON 数组写入 `<file>`（stdout 仍只输出问题）；在只运行一个评审者的 Codex 宿主上使用它。问题可携带 `emet review` 下描述的可选字段 `s` 和 `userOption`。
- `emet launch <spec-id> --wave <n>`: 在此宿主上，启动一个运行 `$emet:run --dispatch <spec>` 的分离 `codex exec`，并记录其线程 ID。不会打开 Orca 标签页，`codex exec resume <id>` 可继续该会话。
- `emet guard`: 在 `EMET_AGENT_HOST=codex` 下读取 Codex 的 hook 输入，对照 `.emet/surface.json` 检查 `apply_patch` 的路径，并在收到提示行 `approve <id>` 之前保持批准闸门关闭。

| 评审           | `emet review --ticket <t> --findings <file>`         | 维护问题台账，并强制执行分诊顺序（`intent_gap` → `bad_plan` → `patch` → `defer`）和轮数上限。`--base <ref>` 在第一轮把 `<ref>` 解析为 sha 并保存；之后的轮次沿用它，不同的 sha 会以退出码 2 退出并指出已保存的那个。对 diff `<base>..HEAD` 既未新增也未修改的行提出的问题，会以 `preexisting: true` 保存，`emet gate` 不将其计为阻塞项。问题接受可选的 `s: "S<n>"`（相关的需求）、`userOption: "S<n>"`（与 `(user option)` 需求相矛盾的问题：始终阻塞，即使早已存在；在 `gate.onHold: fix-and-continue` 下会得到 `hold` 且 `next: fix-findings`）以及 `agreement: "both"` 或 `"single"`；非字符串的 `userOption` 以退出码 2 退出。`--coverage <file or -> [--expect S1,S3]` 把 Coverage verdicts 的 JSON 数组 `{s, verdict, test:{file,name}}`（`verdict`：`met`、`partial`、`unmet`）存为台账的 `coverage`，替换之前的内容，且不占用评审轮次。对于 `test` 缺失、文件不存在或不含 `test.name` 的每个 `met`，以及没有 verdict 的每个 `--expect` S#，它会开出一个 `VG-S<n>` 问题（major，`patch`）。`VG-` 问题只有在之后的 `--coverage` 不再产生它，或某个 recheck verdict 将其解决时才会关闭，绝不会因为在某轮 `--findings` 中缺席而关闭。它输出 `{coverage, open}`，只要有任何问题处于打开状态就以退出码 1 退出；它不运行测试。`--merge <a.json> <b.json>`（不带 `--ticket`）输出一个合并后的问题数组供 `--findings -` 使用：两个问题在共享 `s`，或共享 `file` 且行号相差不超过 3 时配对，配对后保留第一个文件的 `id`、更高的严重程度以及 `agreement: "both"`。未配对的问题获得 `agreement: "single"`，来自第二个文件的冲突 id 会加前缀 `X-`；`userOption` 问题绝不会被丢弃。`--recheck --verdicts <file>` 结束一轮修复：只评估该轮开始时未处理的问题，问题只能通过裁决变为 `resolved`，且 recheck 计入 `budgets.fixRounds`（用尽时以退出码 1 并指明上限）。`--escalate` 升级到下一个模型层级。`--rule`/`--rulings` 记录并列出用于报告和 PR 正文的“我做出的裁定”。 |
| 合并或串联     | `emet gate <ticket> --tier … --ci … --integration …` | 以 JSON 打印 `merge`、`hold`、`chain`、`stop` 或 `defer` 及其原因。它会读取 verify 记录、未处理的问题、风险层级、CI、集成套件和预算。`hold` 带有 `next`：`fix-findings`、`rerun-failed-specs`、`rerun-ci` 或 `report-infrastructure`。`--no-record` 使该决定不写入日志。参见 [`gate`](configuration.md#gate)。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

一个波次的各分支合并到一起之后，`commands.fullSuite` 会在集成分支上运行一次。运行失败会阻止 PR 和 `autoChain`。关卡以 `--integration` 接收这一结果。关卡所读取的预算，参见 [`budgets`](configuration.md#budgets)。

## 退出码

退出码在所有子命令中含义一致。

| 代码 | 含义                                                   |
| ---- | ------------------------------------------------------ |
| `0`  | 一切正常。                                             |
| `1`  | 存在需要处理的问题。                                   |
| `2`  | 配置或用法错误；工具实际上并未运行。未知命令也属此类。 |
| `3`  | 内部错误。                                             |

未知标志同样以 `2` 退出，并指出该标志。Ctrl-C 以 `130` 退出。

## 全局标志

每个命令都接受这些标志；各命令自己的标志可用 `emet <command> --help` 查看。

| 标志         | 作用                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------ |
| `--json`     | 在 stdout 上输出一个信封 `{ok, data, error: {code, message, fix}}`，`--help` 和 `--version` 也是如此。 |
| `--no-color` | 禁用 ANSI 颜色。颜色还遵循 `NO_COLOR`、`FORCE_COLOR`、`TERM=dumb` 以及输出是否为 TTY。                 |
| `--verbose`  | 输出意外错误的堆栈。不加此标志时，顶层 catch 只输出一行错误。                                          |
| `--help`     | 输出该命令的用法。                                                                                     |

`emet --version` 输出版本；`emet --version --json` 输出 `{"ok": true, "data": {"version": ...}, "error": null}`。在 `--json` 下，失败的命令以其通常的退出码退出，并输出 `ok: false`，错误 `code` 为 `findings`、`usage`、`internal`、`slice-timeout`、`expired`、`bad-range` 或 `exit-<n>` 之一；命令在 stdout 上输出的内容即为信封的 `data`。

在 TTY 上，当已知有更新的版本时，`emet` 会在 stderr 上输出一行通知。它每天最多检查一次，缓存结果，从不等待网络，并且在 `--json` 下或没有 TTY 时保持静默。

## 环境变量

面向用户的变量。设置后，变量会覆盖对应的配置值。

| 变量                          | 作用                                                                                                                                                                    |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `EMET_SKIP_DEPENDENCY_CHECKS` | `EMET_SKIP_DEPENDENCY_CHECKS=1 emet preflight` 仅对这一次运行，把依赖检查造成的阻止降级为警告。请在你自己的 shell 中设置，不要设置在协调者无人值守运行的任何内容中。    |
| `EMET_MAX_LIVE_WORKERS`       | 覆盖 [`concurrency.maxLiveWorkers`](configuration.md#concurrency)；接受正整数或 `auto`。                                                                                |
| `EMET_RUN_IDLE_THRESHOLD_MS`  | 覆盖 [`concurrency.runIdleThresholdMs`](configuration.md#concurrency)，单位为毫秒。                                                                                     |
| `EMET_STATE_DIR`              | 主机级状态目录，其中存放工作者槽位池。解析顺序：`$EMET_STATE_DIR`，然后是 `$XDG_STATE_HOME/emet`，最后是 `~/.local/state/emet`。                                        |
| `EMET_MEM_RESERVE_GIB`        | 必须保持空闲的内存余量（GiB）；可用内存低于该值时，获取槽位会被拒绝。默认为 8。它也参与 `auto` 工作者上限的计算。                                                       |
| `EMET_MEM_PER_WORKER_GIB`     | 当 `maxLiveWorkers` 为 `auto` 时，假定每个工作者占用的内存（GiB）。默认为 2。如果每个工作者的技术栈更重，例如每个工作树都运行由浏览器驱动的端到端测试套件，请调高该值。 |
| `EMET_CPU_OVERSUBSCRIBE`      | `auto` 工作者上限所用的 CPU 倍数。默认为 1。                                                                                                                            |
| `EMET_AUTO_UPDATE`            | `EMET_AUTO_UPDATE=0` 会禁用 `emet self update --auto`：它不进行任何网络调用并以退出码 0 退出。与 `emet self update --auto off` 相同。                                   |
| `EMET_AGENT_HOST`             | 设为 `codex` 时，`emet guard` 读取 Codex 的 hook 输入。由 Codex 的 hook 设置；在 Claude Code 上请保持未设置。                                                           |

`auto` 上限为 `clamp(min(cpuCount × EMET_CPU_OVERSUBSCRIBE, floor((memTotal − EMET_MEM_RESERVE_GIB) / EMET_MEM_PER_WORKER_GIB)), min, max)`。旧版的 `FORGE_*` 名称仍然会被读取；两者同时设置时，`EMET_*` 优先。
