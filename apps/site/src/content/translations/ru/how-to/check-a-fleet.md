Проверяйте, изменяйте и запускайте emet сразу в нескольких репозиториях. Термины соответствуют [GLOSSARY.md](../../GLOSSARY.md).

## Предварительные требования

- emet установлен; см. [Установка](../start/install.md).
- В каждом репозитории есть `emet.config.json`, и он находится на один уровень ниже одного корня (по умолчанию `~/code`).
- `gh` есть в `PATH` и авторизован; см. [справочник по зависимостям](../reference/dependencies.md).

## Проверка репозиториев

:::steps

1. Запустите аудит только на чтение для любого числа репозиториев:

   ```bash
   emet doctor ~/code/*
   ```

2. Прочитайте отчёт по каждому репозиторию: корректный `emet.config.json`, все четыре файла `docs/agents/*.md`, отсутствие оставшихся маркеров `TODO(emet):`, команды `commands.selfCheck`, которые разрешаются, и результаты проверки зависимостей трекера этого репозитория.
3. Прочитайте общие для обхода результаты, которые выводятся один раз: плагин mattpocock-skills и флаги внешних CLI, проверяемые через `--help` (`gh`, а также в Claude Code `claude --bg` и `claude agents --json`, в Codex `codex exec --json` и `--output-schema`). Переименованный флаг сообщается здесь, ещё до того как сорвёт волну.

:::

## Изменение настройки в каждом репозитории

:::steps

1. Выведите, что есть сейчас в каждом репозитории:

   ```bash
   emet fleet list --root ~/code
   ```

   Команда выводит для каждого репозитория путь, `tracker.kind`, `handoff.autoChain` и `models.worker`; `--json` выводит это как данные.

2. Просмотрите изменение заранее:

   ```bash
   emet fleet set handoff.autoChain false --dry-run
   ```

   `--dry-run` ничего не записывает и выводит для каждого репозитория старое и новое значение.

3. Примените его, выполнив ту же команду без `--dry-run`. Сначала значение проверяется загрузчиком конфигурации; неверное значение не изменяет ни один репозиторий и завершается с кодом 1.

:::

## Запуск фичи в нескольких репозиториях

```bash
emet fleet launch --feature "add dark mode" --repos app,site
```

Команда открывает сессию `/emet:run --draft <text>` в каждом репозитории после тех же проверок готовности, что и у `emet chain`. `--repos` ограничивает запуск списком через запятую.

## Просмотр заблокированных сессий

```bash
emet fleet status
```

Команда выводит для каждого репозитория, сколько сессий emet заблокировано в ожидании решения, работает или простаивает, сначала репозитории с заблокированными сессиями. Она читает последние 24 часа глобального журнала и исключает завершённые сессии; `--json` выводит сами сессии. Внутри одного репозитория `emet status` перечисляет их в `sessions`. См. [Внимание и журнал](../concepts/attention-and-journal.md) и [справочник по конфигурации](../reference/configuration.md#attention).

## Проверка

:::steps

1. Снова запустите `emet doctor ~/code/*` и убедитесь, что ни один репозиторий не сообщает о сбое.
2. Запустите `emet fleet list --root ~/code` и убедитесь, что изменённый ключ показывает новое значение в каждом репозитории.
3. Запустите `emet fleet status` и убедитесь, что ни один репозиторий не заблокирован неожиданно.

:::

Каждая проба ограничена 5 с, поэтому зависший `gh auth status` не может заблокировать волну. `preflight.requiredCommands` — это список бинарных файлов, принадлежащий самому репозиторию, которые `emet preflight` и `emet doctor` требуют; см. [справочник по CLI](../reference/cli.md#проверка-флота) и [справочник по конфигурации](../reference/configuration.md#preflight).
