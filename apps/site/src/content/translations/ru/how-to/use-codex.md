Запускайте конвейер emet в Codex CLI вместо Claude Code. Термины соответствуют [GLOSSARY.md](../../GLOSSARY.md); продукт, в котором выполняется запуск, называется **хостом агента**. Вернуться к [оглавлению документации](../README.md).

Как волна выполняется в Codex, а также защита и компромиссы песочницы описаны в разделах [Безопасность](../concepts/security.md) и [Запуски, волны и спецификации](../concepts/runs-waves-specs.md).

## Предварительные требования

- CLI `codex` версии из `codex.minVersion` (по умолчанию `0.167.0`) или новее, с выполненным входом.
- `git` и `gh` в `PATH`; см. [справочник по зависимостям](../reference/dependencies.md).
- Репозиторий с `emet.config.json` (выполните `emet init`, если его нет).

## Установка

:::steps

1. Установите плагин `mattpocock-skills` в Codex:

   ```bash
   codex plugin marketplace add mattpocock/skills
   codex plugin add mattpocock-skills@mattpocock
   ```

2. Установите emet автономной установкой из раздела [Установка](../start/install.md). Она записывает навыки emet в `~/.agents/skills/emet/` и добавляет хуки emet в `$CODEX_HOME/hooks.json` (по умолчанию `~/.codex`), а `config.toml` никогда не изменяет. Она также устанавливает терминальный `emet` и команды и агенты Claude Code в `~/.claude`; в Codex это безвредно.

3. Доверьте хукам. Codex не запускает хук, пока вы ему не доверите: откройте `/hooks` и нажмите `t` на странице событий или подтвердите запрос "Hooks need review" при запуске.

:::

### Необязательно: плагин Codex

Вместо автономной установки можно установить плагин emet:

```bash
codex plugin marketplace add andryorelabs/emet
codex plugin add emet@emet-marketplace
```

Плагин не приносит шим `emet`, поэтому для терминального `emet` по-прежнему нужна автономная установка. `emet self install` отказывается работать, пока установлен плагин, если не передать `--force`, а `emet doctor` предупреждает, когда они сосуществуют.

## Выбор хоста агента

:::steps

1. Задайте `agentHost` в `emet.config.json` (по умолчанию `"claude"`):

   ```json
   { "agentHost": "codex" }
   ```

2. Задайте модели, усилие, минимальную версию и песочницу в секции `codex`, если значения по умолчанию не подходят; см. [справочник по конфигурации](../reference/configuration.md#codex) и [Модели и усилие](choose-models.md).
3. Запустите прогон из Codex командой `$emet:run`. Чтобы запустить волну из терминала, выполните `emet launch <spec> --wave <n>`; она запускает отсоединённый `codex exec` и записывает id его потока, так что `codex exec resume <id>` продолжает его. Вкладка Orca не открывается.

:::

## Подтверждение плана

emet запрашивает одно подтверждение, после плана. В Codex это хук.

:::steps

1. Дождитесь, пока `$emet:run` материализует спецификацию. Пока не существует `.emet/runs/spec<id>/approval.json`, `emet guard` отклоняет любые изменения с причиной `not approved: send approve <id>`.
2. Отправьте строку промпта, которая в точности равна `approve <id>`. Хук `UserPromptSubmit` записывает файл подтверждения. Те же слова в выводе инструмента или в тексте модели ничего не делают.
3. Либо начните с `/plan $emet:run` и подтвердите план в собственном режиме планирования Codex.

:::

## После обновления emet

При автономной установке хуки являются обычными записями в `hooks.json` и остаются доверенными. С плагином Codex снова просит доверять хукам плагина после каждого обновления.

:::steps

1. Откройте `/hooks` и нажмите `t` на странице событий или подтвердите запрос "Hooks need review" при запуске. До этого emet guard и единственное подтверждение не работают.
2. Если шим выводит `release v<version> has no downloadable asset yet`, он запускает версию из кэша. Повторите через несколько минут.

:::

## Проверка

:::steps

1. Выполните `emet doctor .`. На хосте Codex он сообщает о `codex` старее `codex.minVersion`, об отсутствии флага `--json` или `--output-schema` у `codex exec`, о хуках без доверия и об отсутствии `mattpocock-skills`.
2. Исправьте то, о чём он сообщает, по соответствующему пункту раздела [Устранение неполадок](../troubleshooting.md#хост-codex) и запускайте его снова, пока он не перестанет сообщать о сбоях.

:::

Известные ограничения: усилие `ultra` никогда не отправляется и отклоняется в конфигурации, а `codex.sandbox` по умолчанию равен `danger-full-access`, чтобы воркеры могли делать коммиты; задайте `"workspace-write"`, чтобы сохранить песочницу, и тогда воркеры не смогут делать коммиты. См. [ADR-0022](../adr/0022-codex-workers-run-unsandboxed-by-default.md) и [отчёт о пробе](../research/codex-probe-report.md).
