## 0.22.1

2026-11-25

### Исправлено

- `emet promote` открывает синхронизирующий pull request из `main` в `develop` только тогда, когда в `main` есть содержимое, которого нет в `develop`. Поэтому `develop` со слиянием только через squash больше не копит после каждого promote pull request синхронизации, который нельзя смержить. Если различаются только merge-коммиты, ничего не открывается, а `syncReason` объясняет причину.
- Синхронизирующий pull request сливается через `pr.mergeMethod`, а не merge-коммитом.
- `emet promote --hold` записывает маркер в `<git common dir>/.emet/runs/<id>/no-promote`, а не в каталог `promote hold marker`. Маркеры в старых местах по-прежнему удерживают spec.

## 0.22.0

2026-11-24

### Добавлено

- Бинарный файл `emet` встраивает дерево установки (команды, агенты, справочные промпты, хуки, навыки Codex и манифесты плагинов), генерируемое при сборке и проверяемое на расхождения командой `bun run check`, поэтому скомпилированному бинарному файлу не нужен checkout.
- `emet self install [latest|X.Y.Z] [--dry-run] [--from <checkout>] [--force]` устанавливает автономный бинарный файл в `~/.local/share/emet/versions/<v>/` с симлинком `~/.local/bin/emet`, записывает файлы Claude Code и после резервной копии объединяет хуки emet с `~/.claude/settings.json`, не затрагивая чужие хуки. Отказывается работать, если установлен плагин emet, пока не указан `--force`. `--from` воспроизводит установку из исходников на Bun.
- Адаптер Codex команды `emet self install` записывает навыки emet в `~/.agents/skills` и добавляет встроенные хуки в `$CODEX_HOME/hooks.json`, никогда не записывая `config.toml`, и выводит однократный шаг подтверждения доверия через `/hooks`. Оверлей worker для Codex опускает таблицы плагина emet, когда обнаруживает автономную установку.
- `emet self update [latest|X.Y.Z]` и `emet self update --auto` скачивают выпуск, проверяют `SHA256SUMS` (и аттестацию, если есть `gh`) и подготавливают его. Подмена ждёт, пока не останется занятых слотов worker. `--auto` запускается из хука `SessionStart` не чаще одного раза в сутки.
- `scripts/install-remote.sh`, прикреплённый к каждому выпуску как `install.sh`, скачивает бинарный файл, проверяет его контрольную сумму и запускает `emet self install`: `curl -fsSL https://emet.andryore.dev/install.sh | sh`.
- `emet doctor` предупреждает, когда автономная установка и плагин сосуществуют, когда установленные файлы расходятся со встроенным деревом, когда у хука Codex нет записи `trusted_hash` и когда ожидается обновление или автообновление отключено.
- Публикуется `docs/reference/stability.md`, а `docs/specs/translations.md` — новая живая спецификация.

### Изменено

- Документация реорганизована в пять групп: Get started, Concepts, How-to, Reference и Help — на всех десяти языках. Каждый маршрут, опубликованный до этого выпуска, перенаправляет на новый маршрут, а `/docs/` перенаправляет на `/docs/start/overview/`.
- `start/overview`, `start/install` и `start/first-run` содержат единственные инструкции по установке. Автономная установка идёт первой, а плагины помечены как необязательные.
- Страницы Concepts объясняют тему без таблиц конфигурации, `concepts/landing` указывает, что spec по умолчанию попадает как один pull request, а `concepts/architecture` перечисляет все нетестовые модули `emet/src`. Страницы How-to — это шаги задачи с предварительными условиями и проверкой результата, а в `reference/cli` по одному заголовку на команду.
- Главная страница Website показывает один pull request на spec и рассказывает о быстром режиме, памяти, двойном ревью, оповещениях о внимании и обратимой установке.
- `emet uninstall` также удаляет автономные артефакты: каталог версий, симлинк, файл состояния установки, навыки и хуки Codex и каждую команду хука emet в обоих файлах хуков. Изменённые файлы и чужие хуки сохраняются.
- У каждой опубликованной страницы, кроме `whats-new`, есть актуальный перевод на каждом из девяти языков, включая новую страницу `reference/stability`.

### Удалено

- `install.sh` удалён. Его заменяют `emet self install` и команда `curl`, а проверки зависимостей и рекомендации doctor указывают на них.

## 0.21.0

2026-11-23

### Добавлено

- `emet setup --dry-run` (сочетается с `--with`, `--yes` и `--json`) печатает запланированные шаги каждого выбранного элемента или `already-present` и ничего не меняет: не запускает команды и не записывает ни файлы, ни записи журнала.
- `emet setup` записывает каждый элемент с результатом `installed` в журнал setup, `setup-ledger.json` в каталоге состояния, вместе с записями для отката, нужными, чтобы его отменить. Запись в журнал атомарна, а повреждённый журнал вызывает ошибку с указанием его пути.
- `emet setup --restore <id>` откатывает `claude-settings` (прежний `model` и deny-правила, добавленные emet, после резервной копии с отметкой времени) или `firecrawl-local` (прежнюю запись MCP пользовательской области). Любой другой id завершается с кодом 2, а id без записи в журнале завершается с кодом 1.
- `emet uninstall [--dry-run] [--yes] [--purge] [--json]` удаляет установку `install.sh`: файлы манифеста, чей хеш всё ещё совпадает, shim, каждый хук `emet guard` в `~/.claude/settings.json` (после резервной копии с отметкой времени) и дополнения из журнала setup. Изменённые файлы сохраняются и перечисляются. Для глобальных установок brew, bun и cargo печатает команду удаления и никогда её не запускает.
- `./install.sh --uninstall [flags]` запускает `emet uninstall`.
- `docs/reference/cli.md` и `README.md` описывают журнал setup, `--dry-run`, `--restore` и `emet uninstall` на всех девяти языках.

## 0.20.0

2026-11-22

### Добавлено

- `emet guard` записывает в журнал событие `session.attention`, `{sessionId, state, from, trigger}`, когда сессия, принадлежащая emet, меняет состояние между `working`, `idle`, `needs-decision` и `ended`. Событие добавляется только если состояние отличается от последнего записанного для этой сессии. Журнал никогда не хранит текст уведомлений, промпты и входные данные инструментов, а запись никогда не меняет вердикт guard, его stdout или код завершения.
- `hooks/hooks.json` и `install.sh` подключают события хуков `Notification`, `PermissionRequest`, `SessionEnd` и `UserPromptSubmit` к `emet guard --event <Event>`. `install.sh` остаётся идемпотентным. `codex/hooks.json` не меняется.
- JSON команды `emet status` получает `sessions: [{sessionId, state, blocked, since, runId}]` — последнее состояние каждой сессии репозитория за последние 24 часа, кроме `ended`. Заблокированная сессия переводит общее состояние в `needs-decision` и упоминается в строке сводки и в `--brief`.
- `emet fleet status [--json]` выводит последние состояния сессий по репозиториям из глобального журнала, сначала заблокированные репозитории.
- При переходе в `needs-decision` emet поднимает одно оповещение: отметку непрочитанного и комментарий на worktree репозитория в Orca, если Orca доступен, иначе `notify-send`, если он есть в PATH. `attention.alert` (булево значение, по умолчанию `true`) добавлен в схемы конфигурации и отключает его.
- `docs/reference/cli.md`, `docs/reference/configuration.md` и `docs/guide/fleet.md` описывают функции внимания к сессиям на всех девяти языках.

## 0.19.0

2026-11-22

### Добавлено

- `emet memory search --json <query> [--limit <n>]` и `emet memory save --json --key <spec-<id>|quick-<runId>> --run <runId> --outcome <outcome>` читают и записывают Lessons в Engram. `search` оставляет заметки, topic key которых начинается с `emet/<repo>/lessons/`, и выводит их полное содержимое, `save` добавляет по одному разделу на run в заметку spec или quick run из 1–5 bullets со stdin. Обе команды выводят один JSON-объект, завершаются с кодом 0 при любой проблеме Engram и с кодом 2 только при неверном использовании.
- `memory.enabled` (`auto` или `off`, по умолчанию `auto`) добавлен в схемы конфигурации. `off` никогда не запускает `engram`.
- Phase 1 ищет в памяти прежние Lessons перед первым раундом интервью и записывает релевантные под `## Prior lessons` в файл плана. Передачи wave и quick сохраняют Lessons run до итогового отчёта. `--draft` ничего не сохраняет.
- `docs/reference/cli.md` и `docs/reference/configuration.md` описывают `emet memory` и `memory.enabled` на всех девяти языках.

### Изменено

- Сборка Codex отклоняет `mcp__engram` в сгенерированной справке, поэтому имена инструментов Engram никогда не попадают в плагин Codex.
- Промпты `/emet:run` получают описанные выше шаги памяти; если `engram` нет в PATH или задано `memory.enabled: "off"`, каждый шаг сводится к однострочной заметке, и run продолжается как в 0.18.0.

## 0.18.0

2026-11-22

### Добавлено

- `emet review --ticket <t> --coverage <file|-> [--expect S1,S3]` сохраняет Coverage verdicts в ledger. Вердикт `met`, тест которого отсутствует или не найден в рабочем дереве, и ожидаемый S# без вердикта открывают по одному finding `VG-S<n>`.
- `emet review --base <ref>` сохраняет базу ревью в первом раунде и помечает как `preexisting` finding на строке, которую wave не трогала. `emet gate` никогда не считает ранее существовавший finding блокирующим.
- Findings принимают необязательные поля `s`, `userOption` и `agreement`. Открытый finding с `userOption` блокирует на любом уровне и при любой severity, а gate отвечает `hold` с `next: "fix-findings"`. Phase 2 записывает S#, пришедший из выбранной пользователем опции, как `(user option)`.
- `emet review --merge <a.json> <b.json>` объединяет два массива findings в один. Findings образуют пару, если у них общий `s` или общий `file` со строками не дальше 3 друг от друга, и получают `agreement: "both"` или `"single"`.
- `emet assess` выводит `dualReview: {run, reason}`, а `review.dual` (`auto` или `off`, по умолчанию `auto`) добавлен в схемы конфигурации. На хосте Claude при наличии `codex` в PATH wave уровня `high` запускает Dual review: `emet:emet-reviewer` и `emet review-run --tier high --coverage-out <file>` параллельно, затем `emet review --merge`.
- `emet review-run --coverage-out <file>` записывает Coverage verdicts ревьюера Codex, а его схема вывода принимает `s` и `userOption` со значением null.
- `docs/reference/cli.md` и `docs/reference/configuration.md` описывают изменения ревью на всех девяти языках.

### Изменено

- Промпт ревьюера и `agents/emet-reviewer.md` запрашивают файл Coverage verdicts `.emet/coverage-<run>.json` вместо строки прозой `S<n>: met | partial | unmet`. Phase 8 записывает вердикты через `emet review --coverage` и перечисляет ранее существовавшие findings в отчёте wave, не исправляя их.
- Без `--base`, `--coverage`, `--merge` и Dual review каждая команда ведёт себя как в 0.17.0.

## 0.17.0

2026-11-22

### Добавлено

- `/emet:run --quick <изменение>` запускает Quick run для изменения, которое умещается в один тикет: один раунд интервью, spec с одним folded-тикетом, одно подтверждение, один worker, ревью и Landing этой единственной Wave в виде pull request (или локального merge), без `emet chain`. Перед подтверждением он останавливается и рекомендует `/emet:run` без `--quick`, если изменение затрагивает экран или не умещается в один тикет; вместе с `--draft` или `--dispatch` он отклоняется. `--no-promote` принимается. Шаги описаны в новом `emet/reference/phases-quick.md`. См. ADR-0039.
- `emet assess --quick` выводит обычный JSON плюс `"quickRejected"` и завершается с кодом `1`, когда уровень равен `high`. Quick run считает это Stop гейта: без auto-merge, pull request остаётся открытым, а итоговый отчёт называет причины высокого риска. Без `--quick` вывод и коды завершения не меняются.
- `emet approve --quick` записывает `"mode": "quick"` в `approval.json`. Записи, сделанные до этого изменения, по-прежнему проходят `--check`.
- `resolveLandingUnit(config, runId, root)` возвращает `wave` для запуска, подтверждённого с `--quick`, и `config.landing.unit` в остальных случаях. `emet landed`, `emet status` и `emet preflight` читают единицу landing через неё, поэтому Quick run никогда не ожидает ветку spec.
- `emet validate` сообщает об ошибке `no-tickets`, когда в плане нет тикетов, и предлагает написать один folded-тикет.
- `docs/reference/cli.md` и `docs/guide/trackers-and-landing.md` описывают Quick run на всех девяти языках.

### Изменено

- Фраза о быстром пути в `phases-1-5.md` теперь предписывает для запроса ниже порога написать один тикет с пометкой `folded`, а не оставлять план без тикетов.
- `emet preflight --approval <run>` определяет единицу landing по записи подтверждения этого запуска, когда `--run` не указан.

## 0.16.0

2026-11-21

### Добавлено

- Живые спеки, по умолчанию выключены. При `specs.enabled: true` на последней волне спеки координатор записывает дельты требований `ADDED`/`MODIFIED`/`REMOVED`, один раз запускает `emet spec-merge --spec <id>` в интеграционной ветке этой волны перед её ревью и коммитит обновлённый `docs/specs/<area>.md`, так что изменение проходит ревью и приземляется в том же pull request. Новый справочный файл `living-specs.md` описывает формат дельт и правило повторной попытки. См. ADR-0038.
- `specs.enabled` (по умолчанию `false`) в конфигурации и в обеих копиях схемы. `emet init` записывает `"specs": { "dir": "docs/specs", "enabled": false }`.
- `emet doctor` предупреждает, только когда `specs.enabled` равен `true`, если `specs.dir` попадает в gitignore или является файлом. Отсутствие `specs.dir` предупреждением не считается.
- `emet spec-merge --spec <id> --deltas-dir` создаёт и выводит общий каталог дельт `<git common dir>/.emet/runs/<id>/spec-deltas` и завершается с кодом `0`, ничего не сливая.
- `landing.specMergeMethod` принимает `merge` (по умолчанию), `squash` и `rebase`, чтобы спека могла приземляться в trunk, где разрешены только squash-слияния. `emet doctor` предупреждает, если настройки репозитория или ruleset trunk запрещают настроенный метод. См. ADR-0037.
- `bun run check:codex` завершается ошибкой, если в сгенерированном каталоге `codex/` есть файл без источника.

### Изменено

- При выключенном `specs.enabled` `emet spec-merge` выводит `specs.enabled is false; nothing merged` и завершается с кодом `0`. Он читает дельты из общего каталога запуска под git common dir, а при его отсутствии — из `.emet/runs/<id>/spec-deltas/` конкретного checkout.
- Промпты Фазы 8 больше не запускают `emet spec-merge` после приземления волны или спеки; вместо этого `phases-8-review.md` на последней волне загружает `living-specs.md`.
- `emet spec-branch land` ждёт проверки pull request тем же поллером, что и `emet ci`, продолжая опрос, даже если у pull request пока нет проверок, и сливает с `landing.specMergeMethod`.

### Исправлено

- `emet spec-branch land` больше не сливает до того, как GitHub зарегистрировал хоть какие-то проверки.
- `emet setup` перечисляет плагины Claude один раз вместо до трёх, а его тихие пробы завершаются по тайм-ауту, а не зависают.
- `emet doctor` перечисляет установленные плагины один раз за запуск.
- `bun run lint` и `bun run fix` сначала генерируют типы Astro для сайта, поэтому проходят на свежем checkout.

## 0.15.0

2026-11-21

### Изменено

- `landing.unit` по умолчанию равен `spec`: волны спеки интегрируются в ветку `spec/<id>` командой `emet spec-branch`, а спека приземляется один раз, одним pull request (или одним локальным слиянием при `landing.mode: merge`), вместо отдельного pull request на каждую волну. Чтобы сохранить прежнее поведение, задайте `"landing": { "unit": "wave" }`. Режиму `spec` нужен `worktree.baseRef: "head"` в настройках Claude Code. См. ADR-0037.
- В журнале появились виды `spec.integrate`, `spec.land` и `spec.abandon`, а в `emet status` — поле `specBranch`.

## 0.14.5

2026-11-21

### Добавлено

- `emet handoff --check` разбирает раздел `skills:` в заметке передачи воркера (`none` или `loaded: a, b; missing: c`). Он обязателен, когда `state` равен `done`. `--expect-skills a,b` завершает проверку ошибкой для каждого указанного навыка, которого нет ни в одном из двух списков, и выводит недостающие.
- Запись диспетчеризации получила необязательный массив `skills`, а `emet verify` передаёт его в `emet handoff --check` как `--expect-skills`. Запись без `skills` по-прежнему разбирается.
- ADR-0036 позволяет тикету менять формулировку установленного промпта, если он называет абзацы, а тот же pull request поднимает лимиты в байтах.

### Изменено

- Промпт фазы 8 разделён на `phases-8-review.md` и `phases-8-landing.md`. `install.sh` выводит из обращения старый `phases-8-closeout.md`: изменённая копия или копия до появления манифеста перемещается в `phases-8-closeout.md.retired`, неизменённая копия удаляется.
- Промпт воркера велит записать строку `skills:` перед финальной передачей.
- Страница архитектуры, справочник по CLI и их девять переводов описывают два файла фазы 8 и `--expect-skills`.

## 0.14.4

2026-11-20

### Добавлено

- `emet doctor` на хосте Codex предупреждает, когда плагин emet включён в `$CODEX_HOME/config.toml`, но Codex не доверяет ни одному из его хуков, поэтому защита emet не запускается. Предупреждение не меняет код выхода.

### Исправлено

- Если ресурс релиза для версии плагина пока нельзя скачать, `bin/emet` запускает самый новый кэшированный бинарный файл для любой команды, а не только для `emet guard`, и выводит одно уведомление о том, что релиз, возможно, ещё публикуется. При `EMET_PREFETCH=1` он выводит уведомление и завершается с кодом `0`, ничего не запуская. Несовпадение контрольной суммы или отсутствие `SHA256SUMS` по-прежнему никогда не приводят к откату на кэш, а временный каталог загрузки удаляется до отката.

## 0.14.3

## 0.3.0

2026-11-05

### Добавлено

- Команды плагина `/emet:init` и `/emet:doctor` запускают `emet init` и
  `emet doctor .` внутри Claude Code и кратко излагают результат.
- `emet doctor` предупреждает о хуках `forge guard` и `emet guard` в
  `~/.claude/settings.json`, бинарного файла которых больше нет, и выводит
  команду, которая сначала делает резервную копию, а затем удаляет их через `jq`. Файл он никогда не правит.

  мода, остальные записыватели фаз и растровые кадры.
- `emet-mascot` — необязательный плагин, который показывает пиксельного маскота над строкой ввода
  и отражает сессию и фазу запуска `emet`. Он включён в
  маркетплейс, с руководством по питомцу Orca и ADR-0016.

### Исправлено

- Плагин больше не предоставляет сломанную дублирующую команду `/emet:emet`;
  `commands/` закреплён за `run.md`, `init.md` и `doctor.md`.
- Следующая волна теперь запускается через `/emet:run` — команду, которую
  регистрирует плагин.

- Репозиторий переехал в организацию GitHub `andryorelabs`. Загрузки релизов,
  бейджи README и URL для клонирования теперь указывают на
  `andryorelabs/emet`; старые URL `AndryOre/emet` по-прежнему перенаправляют.
- Автономные установки переименовывают `/emet` в `/emet:run`, как и плагин.
  `install.sh` теперь устанавливает `commands/run.md`, `init.md` и `doctor.md` в
  `~/.claude/commands/emet/`, поэтому `/emet:run`, `/emet:init` и `/emet:doctor`
  доступны и без плагина. Старый `~/.claude/commands/emet.md` удаляется,
  если не был изменён; изменённая копия сохраняется и указывается в
  итоговой сводке установки.

## 0.2.0

2026-11-05

### Изменено

- Проект переименован из claude-forge в emet: CLI называется `emet`,
  команда — `/emet`, агенты — `emet-worker` и `emet-reviewer`, а
  README получил новый бренд. Существующие установки и репозитории продолжают работать:
  устаревшие имена (`forge.config.json`, `.forge/`, `docs/agents/forge.md`,
  `FORGE_*`) по-прежнему читаются с уведомлением, а `emet migrate` переводит репозиторий на
  новые имена.

### Добавлено

- `install.sh` работает без Bun: он устанавливает шим автономного бинарного файла как
  `~/.local/bin/emet`, переписывает плейсхолдеры плагина в копируемых промптах,
  устанавливает `commands/run.md` как `~/.claude/commands/emet.md` и принимает
  `shasum -a 256` вместо `sha256sum`.
- README описывает реальные требования, оба способа установки и
  порядок: сначала `/setup-matt-pocock-skills`, затем `emet init`.
- Руководство для агентов (`AGENTS.md`), доменный глоссарий (`GLOSSARY.md`) и
  записи архитектурных решений в `docs/adr/`.
- Локальный markdown-трекер по соглашению `.scratch/` с CLI `emet tracker`
  (`create-spec`, `create-ticket`, `frontier`, `set-state`, `comment`,
  `close`) и поддержкой локального режима в `emet validate`, `preflight` и `doctor`.
- `landing.mode` (`pr` или `merge`) и `emet land`, который приземляет волну как одно
  локальное слияние без PR; `emet cleanup` и `emet status` сравнивают с локальным trunk
  в режиме merge.
- Автономные бинарные файлы `emet`, `emet --version`, поддержка macOS в CI и в
  тормозе по дереву процессов и памяти, а также манифесты плагина с шимом `bin/emet`.
- Контракт навыков с `emet skill-path` и расширенный `emet doctor`, охватывающий
  навыки, глоссарий, устаревшие элементы и двойные установки.
- Не зависящие от языка `emet init` и `emet map` для репозиториев JS, Go, Rust и Python.
- ADR-0007 – ADR-0011.
- Указатель документации, карта кода архитектуры, устранение неполадок по симптомам,
  более богатый шаблон PR и `emet/AGENTS.md` с правилами только для времени выполнения.

### Изменено

- `gh` нужен только если `tracker.kind` равен `github` или `landing.mode` равен
  `pr`.
- `emet init` больше не выбирает локальный трекер по умолчанию.
- ADR-0004 изменён: волна приземляется как один PR или одно локальное слияние.
