Уже используете emet в нескольких репозиториях? `emet doctor` проверяет любое их число за один проход, только на чтение:

```bash
emet doctor ~/code/*
```

Для каждого репозитория отчёт показывает: корректный `emet.config.json`, наличие всех четырёх файлов `docs/agents/*.md`, отсутствие оставшихся маркеров `TODO(emet):`, действительно ли разрешаются команды из `commands.selfCheck`, а также результаты проверки зависимостей, специфичных для трекера этого репозитория (`gh`, Linear; см. [справочник по зависимостям](../reference/dependencies.md)). Плагин mattpocock-skills и флаги внешних CLI (`gh`, `claude --bg`, `claude agents --json`, проверяются через `--help`) проверяются один раз на весь обход, а не для каждого репозитория.

`emet doctor` проверяет сами флаги, а не только наличие бинарных файлов. Он читает `--help` для `gh issue view`/`gh repo view` (`--json`), `gh issue edit` (`--add-label`, `--remove-label`), `claude` (`--bg`) и `claude agents` (`--json`) и сообщает о каждом флаге, который более новая или более старая версия CLI больше не документирует. Переименованный флаг иначе сорвал бы волну на полпути.

Каждая проба ограничена 5 с, чтобы зависший `gh auth status` (без сети) не мог заблокировать волну. `preflight.requiredCommands` репозитория — это список бинарных файлов, принадлежащий самому репозиторию, которые `emet preflight` и `emet doctor` требуют в PATH. См. [справочник по CLI](../reference/cli.md#проверка-флота) и [справочник по конфигурации](../reference/configuration.md#preflight).
