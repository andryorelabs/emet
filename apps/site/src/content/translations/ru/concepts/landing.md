Как спецификация садится, по умолчанию одним pull request. Термины соответствуют [GLOSSARY.md](../../GLOSSARY.md).

Здесь **Landing** (посадка) означает, как законченная работа попадает в trunk. К главной странице Website это не имеет отношения.

## Один pull request на спецификацию

По умолчанию спецификация садится одним pull request. Каждая волна по-прежнему проходит собственное ревью, гейт и самопроверку, но прошедшая волна не садится. Координатор сливает её интеграционную ветку с `--no-ff` в локальную **Spec branch** (ветку спецификации) `spec/<id>`, и тикеты волны становятся **Integrated**. Следующая волна ответвляется от вершины этой ветки, так что последующие волны строятся на предыдущих, не дожидаясь CI для pull request.

После последней волны координатор синхронизирует trunk в ветку спецификации слиянием, а не перебазированием, и сажает её один раз: один pull request или одно локальное слияние, если режим посадки — `merge`, который никогда ничего не отправляет. Каждая волна остаётся отдельным коммитом слияния в истории trunk, поэтому одну волну всё ещё можно откатить.

Тикет **Integrated** считается закрытым блокером для **Frontier** (фронтира), но остаётся открытым, пока его не закроет итоговая посадка. **Landed** сохраняет своё простое значение: он в trunk.

## Волна садится отдельно только по запросу

При `landing.unit: wave` каждая волна садится сама: один pull request и одно ожидание CI на волну, а следующая волна начинается только после слияния этого pull request. Тогда спецификация из трёх волн стоит трёх pull request. Так работало до [ADR-0037](../adr/0037-landing-per-spec.md), и этот вариант остаётся доступным.

**Quick run** (быстрый запуск) всегда садится по волнам, потому что в нём ровно одна волна. См. [ADR-0039](../adr/0039-quick-mode-lands-per-wave.md).

## Pull request или локальное слияние

Независимо от единицы, `landing.mode` определяет, как работа попадает в trunk. `pr` открывает pull request и требует `gh`. `merge` сливает локально командой `emet land` или `emet spec-branch land` и никогда ничего не отправляет, а вместо CI выступает команда самопроверки репозитория. См. [ADR-0010](../adr/0010-local-merge-landing.md).

## Чего ожидать

- Дефект, который ловит только CI, обнаруживается при итоговой посадке, после того как на нём построены следующие волны.
- Конфликт с trunk обнаруживается при синхронизации, где координатор останавливается и перечисляет пути.
- Рабочая копия привязана к одной спецификации за раз; вторая спецификация параллельно требует другого worktree.
- `spec/<id>` по умолчанию отправляется после каждой интегрированной волны без открытия pull request, поэтому потеря диска стоит не больше одной волны.
- Слияние pull request спецификации коммитом слияния сохраняет откат по волнам. Trunk, допускающий только squash-слияния, сажает спецификацию одним коммитом и теряет этот откат.

Ключи описаны в [`landing`](../reference/configuration.md#landing). Команды — в [`emet spec-branch` и `emet land`](../reference/cli.md#planning-review-and-landing). Решение — в [ADR-0037](../adr/0037-landing-per-spec.md).
