# 0023. CLI-owned mailbox for Codex workers

Status: Accepted (2026-11-10)
Spec: the Codex worker mailbox and cross-run surface overlap spec, filed 2026-11-10

## Context

A Claude Code worker escalates to its coordinator with `SendMessage`. A Codex worker runs as a `codex exec` process with no stdin and nothing that resumes it ([ADR-0021](0021-codex-support-strategy.md)), so the generated Codex prompts can only tell it to state the question in its handoff note and exit, which loses the worker's context. The Agent host is chosen per repo, so a coordinator and its workers always share one Agent host; there is no mixed mode.

## Decision

- The `emet` CLI owns a file **Mailbox** under `<git-common-dir>/.emet/runs/<run>/mailbox/<ticket>/`. A worker records a question with `emet ask` and polls for the reply with `emet ask --wait`; the coordinator reads open questions with `emet inbox` and answers with `emet reply`.
- Only Codex uses it. Claude Code keeps `SendMessage`, and its installed prompts stay byte-identical for this part. The CLI does not depend on the Agent host, so a future mixed mode can reuse it.
- A worker waits in short slices and gives up with a BLOCKED result once `budgets.askWaitMinutes` (default 30) has passed.
- `emet dispatch --wait` returns status `question` while a worker has an open question, and never classifies that worker as stalled.
- The mailbox is a worker-to-coordinator channel only. Workers never message each other, and the coordinator stays the single tracker writer ([ADR-0005](0005-coordinator-is-the-single-tracker-writer.md)).

## Consequences

- A Codex worker keeps its context across a question instead of ending the run.
- A wait of up to `budgets.askWaitMinutes` holds a **Slot** while the worker does nothing.
- The Codex exec policy allows `emet ask`, and the Codex prompts are generated by new rules in `tools/build-codex.ts`; the Claude install is untouched by this decision.

## Alternatives considered

- **Mailbox on both Agent hosts**: rejected. Polling would replace a native channel on Claude and rewrite its installed prompts for no gain.
- **Ask and exit**: rejected. The coordinator would re-dispatch with the answer and the worker would lose its context.
- **Worker-to-worker messages**: rejected. They contradict ADR-0005 and make waves less predictable.
