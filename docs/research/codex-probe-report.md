# Codex probe report

The real-Codex check of every `unverified` point in [Running emet on Codex](../guide/codex.md), made by `tools/codex-probe.ts` (`EMET_CODEX_PROBE=1 bun run probe:codex -- --flow`). Terms follow [GLOSSARY.md](../../GLOSSARY.md). Background: [the viability research](codex-viability.md).

Run on 2026-11-09 against `codex-cli 0.167.0`, signed in with a ChatGPT free plan, on Linux. Every model run used effort `low` and the cheapest resolved model (`gpt-6-luna`), with a 15 minute cap. No run hit a plan limit, so no row is `blocked-by-plan-limit`. Each run used a throwaway repo under `/tmp` with no remote.

Verdicts: `verified` (the behaviour holds), `failed` (it does not, or the evidence cannot show it), `blocked-by-plan-limit` (a rate or usage limit answered twice), `not-applicable`.

## E2E

`EMET_CODEX_E2E=1 bun test tools/codex-e2e.test.ts` (with `CODEX_HOME` pointing at an auth-only copy, so `~/.codex/config.toml` is not written): **failed**. `emet dispatch` started the worker, but `dispatch lands a commit and refuses git push` found 0 commits on the worker branch. The same run inside the full flow shows why: in the `workspace-write` sandbox, `git add` fails with `Unable to create '<repo>/.git/worktrees/agent-<ticket>/index.lock': Read-only file system`, although `emet dispatch` passes `--add-dir <git-common-dir>`. The push assertion was not reached.

## Follow-ups

- `buildRunHome` must not symlink `config.toml`: `codex exec` writes project trust through it into `~/.codex/config.toml`, breaking the read-only rule. Write a minimal overlay config instead, with the trust key for the run's directories set in the overlay.
- Rules evidence: a command refused by `rules/default.rules` emits no `exec --json` item. Confirm the rule with `codex execpolicy` (or another source) and fix `pushWasRefused` in `tools/codex-e2e.test.ts`.
- Nested dispatch: a pid recorded inside an outer sandbox is a namespace pid and the inner `codex` produced no events. Record a host-visible identity, or document that `emet dispatch` must not run inside a Codex sandbox.
- Worker commits: the `workspace-write` sandbox keeps `.git` read-only even with `--add-dir <git-common-dir>`, so no worker can commit (the e2e and wave 1 both fail). Find a writable-git setting or run git outside the sandbox.
- `emet launch`: the run overlay lacks the source home's `plugins/` directory, so `$emet:run` is unavailable in the launched session. Link or mount the plugin cache.
- `emet preflight` (via `agentHostOfConfig` in `emet/src/dependencies.ts`) throws `unknown agent host: codex`: the Codex adapter is registered only in `launch.ts`.
- `emet review-run` sends an unresolved model when the run's models cache is missing. Fall back to a model known to the ChatGPT plan, or fail early with a clear message.

## Manual check

Run these on a throwaway repo in a terminal with `codex` signed in and an `emet` CLI built from `develop`. Report back the item named in each step.

1. `mkdir /tmp/emet-manual && cd /tmp/emet-manual && git init -b develop && git commit --allow-empty -m init`. Expected: `git log --oneline` prints one line. Report: that line.
2. `emet --help | grep -E 'dispatch|review-run'`. Expected: two lines, one per command (an `emet` 0.4.0 prints none). Report: the lines, or "none".
3. `codex plugin marketplace add andryorelabs/emet && codex plugin add emet@emet-marketplace && codex plugin list | grep emet@`. Expected: `emet@emet-marketplace  installed, enabled`. Report: that line.
4. `emet init --tracker local`, then set `"agentHost": "codex"` and `repo.trunk` to `develop` in `emet.config.json`, and `emet preflight`. Expected: preflight exits 0. Report: the exit code and, if it fails, its last line (the probe saw `unknown agent host: codex`).
5. Start `codex` in the repo and send `$emet:run add hello.txt containing hello`. Expected: the reply follows the skill's Phase 0 and asks interview questions; it does not run `emet run`. Report: the first line of the reply.
6. Answer until the plan is shown, then run `ls .emet/runs` in another terminal. Expected: a `spec<id>` directory with no `approval.json`. Report: the `<id>`.
7. In Codex, send `create test.txt now`. Expected: the tool call is denied with `not approved: send approve <id>` and `test.txt` does not exist. Report: the denial text.
8. Send the prompt line `approve <id>` exactly. Expected: `.emet/runs/spec<id>/approval.json` exists. Report: `ls .emet/runs/spec<id>`.
9. Let wave 1 run, then `git -C .emet/worktrees/agent-<ticket> log --oneline -2`. Expected: a ticket commit above `init`. Report: the output, or the `index.lock` error from `.emet/runs/<run>/codex/<ticket>.jsonl` if there is no commit.
10. `grep -c emet-manual ~/.codex/config.toml`. Expected: `0` (nothing about the run written to your Codex config). Report: the count.
